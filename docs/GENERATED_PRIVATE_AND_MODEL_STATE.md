# Generated, private, and model state

Every live path observed during product operation is either portable source or a documented terminal exclusion/representation in the machine manifests.

## Private Python environments

`INSPECTOR/.venv` and `model-api-gguf/api_service/.venv` are reconstructed with CPython 3.14 from committed locks. Installed packages, interpreter links, wheel metadata, and environment bytecode are not copied to Git. System site packages are disabled.

## Build and toolchain state

Ubuntu/CUDA/Windows binaries remain host state. `model-api-gguf/llama.cpp/build` is generated from the pinned source and build lock. CMake caches, Ninja state, object/static/shared libraries, compiler intermediates, UI bundles generated by the build, and `llama-server` are excluded.

## Models and automatic intake

Production GGUF weights, native weights, evaluation artifacts, and download caches are external. The automatic GGUF path accepts one fully copied supported file from the direct `INSPECTOR/MODEL-TEST` inbox after authenticated `WAITING_FOR_MODEL`. It waits for stable metadata and bytes, performs first-model placement through the pinned `llama.cpp` and `llama-server` branch, and never silently replaces a ready model. A candidate, its copy state, and its acceptance result are runtime evidence, not portable source.

## Runtime and databases

Logs, PIDs, locks, status, operations, transactions, recovery records, desired state, SQLite files, WAL/SHM files, and generated service state are mutable local state. Bootstrap initializes only empty current-schema state; subsequent content is owned by runtime transactions.

## Secrets

API keys, peppers, verifier stores, authorization-bearing records, private keys, tokens, and environment secrets are not Git content. A local credential is freshly generated or explicitly imported into owner-only state. Documentation and evidence record only its class and handling rule, never its raw value.

## Cache and temporary state

`__pycache__`, test/tool caches, bytecode, scratch directories, and temporary files are recreated normally and are excluded.

See `SYSTEM_X_EXCLUDED_STATE_MANIFEST.json` for the complete safe path ledger and `SYSTEM_X_DIRECTORY_CONTRACTS.json` for reconstruction roots and empty-directory contracts.
## Readiness and receipt

The authenticated service is healthy at `WAITING_FOR_MODEL` before intake and reaches `READY` only after candidate acceptance. The zero-argument `show-connection` operation reads the stored receipt and exposes `default` as the recommended client model reference without exposing the raw key.
